# Лабораторна 3 — тестування застосунку «Список покупок»

## 1. Функціональні сценарії

| ID | Сценарій | Опис |
|----|-----------|------|
| S1 | Додавання товару | Користувач вводить назву (і кількість), натискає «Додати»; запис зберігається в Room. |
| S2 | Видалення товару | Користувач натискає іконку видалення на рядку; запис зникає з БД. |
| S3 | Позначення «куплено» | Чекбокс змінює `isBought` у Room. |
| S4 | Фільтрація | Чіпи: Усі / Куплені / Не куплені — список відфільтровується. |
| S5 | Сортування | Назва A–Я, Новіші, Куплені спочатку — порядок змінюється. |
| S6 | Пагінація | Показ порціями по 10; кнопка «Завантажити ще». |
| S7 | Синхронізація (mock) | Іконка хмари викликає Retrofit; mock JSON upsert у Room. |
| S8 | Збереження між запусками | Дані в `shopping.db` (Room); після закриття застосунку залишаються. |

**iOS:** не застосовується (проєкт лише Android).

## 2. Тест-кейси (мінімум 2 на функцію: позитивний + негативний)

| ID | Функція | Назва кейсу | Кроки | Очікуваний результат | Тип |
|----|---------|---------------|-------|----------------------|-----|
| TC-01 | Додавання | Валідна назва | Ввести «Молоко», кількість 2, «Додати» | Рядок «Молоко» у списку, кількість 2 | Позитивний |
| TC-02 | Додавання | Порожня назва | Залишити назву порожньою, «Додати» | Новий рядок не з’являється | Негативний |
| TC-03 | Додавання | Дефолтна кількість | Ввести лише назву, поле кількості порожнє, «Додати» | Товар з кількістю 1 (логіка ViewModel) | Позитивний (граничний) |
| TC-04 | Додавання | Дуже довга назва | Ввести >200 символів, «Додати» | Рядок з’являється (обмеження в UI не задані — зафіксовано як спостереження) | Негативний / спостереження |
| TC-05 | Видалення | Успішне видалення | Додати «Тест», натиснути видалити на рядку | Рядок зникає | Позитивний |
| TC-06 | Видалення | Список порожній | Відкрити застосунок без товарів | Кнопок видалення немає | Негативний (немає об’єкта) |
| TC-07 | Збереження (Room) | Після перезапуску | Додати товар, закрити застосунок, відкрити знову | Товар на місці | Позитивний |
| TC-08 | Збереження | Порожня БД | Перший запуск / очищені дані | Повідомлення про порожній список (за фільтром) | Негативний |
| TC-09 | Куплено | Позначити купленим | Увімкнути чекбокс | Закреслений текст, у фільтрі «Куплені» видно | Позитивний |
| TC-10 | Куплено | Зняти позначку | Вимкнути чекбокс | Рядок знову «не куплений» | Позитивний |
| TC-11 | Фільтр | Тільки не куплені | Увімкнути «Не куплені» | Куплені приховані | Позитивний |
| TC-12 | Фільтр | Немає збігів | Усі куплені, фільтр «Не куплені» | Порожній стан / повідомлення | Негативний |
| TC-13 | Сортування | За назвою | Обрати «Назва A–Я» | Алфавітний порядок | Позитивний |
| TC-14 | Сортування | Один елемент | Один товар, змінити сорт | Порядок не ламається | Граничний |
| TC-15 | Пагінація | «Завантажити ще» | >10 товарів, натиснути кнопку | З’являються наступні | Позитивний |
| TC-16 | Пагінація | Менше ніж сторінка | ≤10 товарів | Кнопка «Завантажити ще» відсутня | Негативний |
| TC-17 | Синхронізація | Успішний mock | Натиснути синхронізацію | З’являються товари з mock (srv-*) | Позитивний |
| TC-18 | Синхронізація | Мережа недоступна* | *У цьому проєкті mock не ходить у мережу — кейс N/A або перевірка відсутності crash | Без збоїв | — |

## 4. Автоматизовані тести

- **Інструмент:** Jetpack Compose UI Test (`ui-test-junit4`) + інструментований тест Room (DAO).
- **Розташування коду:** `app/src/androidTest/java/com/example/shoppinglist/`
- **Запуск:** `gradlew.bat connectedDebugAndroidTest` (потрібен емулятор або пристрій).

Опис тест-класів див. коментарі в коді та розділ «Висновок» нижче.
