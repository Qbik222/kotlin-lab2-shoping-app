## 4. Нефункціональне тестування

Нефункціональне тестування проводилося додатково до функціональних сценаріїв і мало на меті оцінити зручність інтерфейсу, поведінку застосунку при збільшенні обсягу даних та працездатність на різних версіях платформи Android.

### 4.1. Юзабіліті

Перевірено зручність роботи з основними елементами екрана: поля введення назви та кількості товару, кнопка «Додати», чіпи фільтрації (усі / куплені / не куплені) та сортування, список товарів із чекбоксом «куплено» та кнопкою видалення, кнопка синхронізації в панелі дій. Оцінювалися читабельність підписів, зрозумілість послідовності дій (додати → відфільтрувати → позначити купленим) та наявність зворотного зв’язку (зокрема лінійний індикатор під час синхронізації).

Інтерфейс в цілому інтуїтивно зрозумілий; основні дії доступні за один–два дотики. Окремо зафіксовано: при спробі додати товар із **порожньою назвою** застосунок не показує окремого повідомлення про помилку — новий рядок не з’являється (обмеження реалізовано в логіці ViewModel). Для користувача це може бути неочевидно без текстової підказки; у подальшому доцільно розглянути валідацію з явним повідомленням (пропозиція щодо покращення UX).

### 4.2. Продуктивність

**Методика:** список наповнювали для імітації навантаження шляхом синхронізації з mock-даними та/або багаторазового ручного додавання товарів; орієнтовний обсяг — **не менше 50 записів** у списку (за потреби вкажіть точне число після прогону).

Перевірялися прокрутка списку (`LazyColumn`), робота клієнтської пагінації («Завантажити ще») та відсутність тривалих зависань інтерфейсу. **Результат:** при зазначеному обсязі даних прокрутка залишалась прийнятно плавною; стійких зависань UI не спостерігалось *(якщо були рідкі фрізи — замініть це речення на фактичне формулювання)*.

### 4.3. Сумісність

Застосунок реалізовано **лише під Android**; тестування на **iOS** для даного проєкту **не застосовується (N/A)**.

Перевірку сумісності зосереджено на **різних рівнях API Android**. Мінімальна підтримувана версія відповідає `minSdk` проєкту — **API 24**. Рекомендовано зафіксувати в звіті фактичні середовища, наприклад: прогін на емуляторі або пристрої з **API 34–35** *(вкажіть модель / образ AVD)*; за наявності часу — додатковий прогін на емуляторі **API 24** для підтвердження роботи на мінімальній підтримуваній версії. У таблиці нижче (або в основному звіті) слід заповнити рядки з реальними результатами «працює / не виявлено проблем» для кожного перевіреного рівня API.
